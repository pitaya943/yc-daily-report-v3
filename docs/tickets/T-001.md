# T-001 專案骨架與測試框架

## 目標

見完成條件。這張 ticket 不對應 spec 的 scenario，以檢查清單驗收。

## 要讀的檔案

只讀這些，不要載入其他 feature 檔。

- `AGENTS.md`
- `spec/README.md`（寫作規約、結果類別）
- `spec/glossary.md`
- `spec/background.md`

## 完成條件

1. FastAPI 應用可啟動；`app/main.py` 自動掃描並註冊 `app/modules/*/*/router.py`。
2. 容器內的 PostgreSQL 17 可用（與共用 Supabase 專案同一主版本，見 D-033；容器沒有 Docker daemon，從 `apt.postgresql.org` 安裝）；所有資料表建立在 `yc_v3` schema；`scripts/dev/migrate` 依編號套用 `migrations/*.sql`。
3. 時鐘由 `app/core/clock.py` 提供，測試可以設定與推進時間；產品程式不得直接呼叫系統時間。
4. pytest-bdd 讀取 `spec/features/*.feature`；每個 scenario 執行前清空資料庫並載入 `spec/background.md` 的固定資料。
5. `tests/implemented.txt` 機制可用：只有列在其中的規則 ID 會被執行，其餘標示為「尚未實作」而不是失敗。
6. 一個冒煙測試從 HTTP 請求走到資料庫並通過。
7. `README.md` 寫明實際的安裝、啟動資料庫、套用 migration、執行測試、啟動應用程式的指令。T-001 合併後由 Chief 搬進 `AGENTS.md` 的「指令」一節（D-030）。
8. Verifier 在乾淨的 checkout 上照 `README.md` 的指令跑完整測試，全部通過，並附 CLI 輸出。這張 ticket 合併前還沒有 CI，以此取代「CI 全綠」（D-032）。
9. 每一條完成條件都附上證據：CLI 輸出貼在 PR 說明；有畫面的功能附截圖，存在 `docs/evidence/T-001/`。
10. PR 說明依 `.github/PULL_REQUEST_TEMPLATE.md` 填寫。
