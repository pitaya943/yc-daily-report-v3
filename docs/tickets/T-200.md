# T-200 固定版本的 HTMX 與共用頁面版型

## 目標

依 D-062 把固定版本的 `htmx.min.js` 放進 repo，並依 D-080 提供所有頁面共用的版型：載入 HTMX，並用 `hx-headers` 把目前 session 的 anti-forgery token 放進標頭 `X-CSRF-Token`。M2 之後每張有畫面的 ticket 都用這個版型，不各自處理 CSRF。

這張 ticket 沒有 scenario；以單元測試與 CLI 證據驗收。

## 要讀的檔案

- `AGENTS.md`
- `docs/decisions.md` 的 D-062、D-078、D-080
- `app/core/session.py`（只讀：`anti_forgery_token_for`、`get_current_actor`、`CSRF_HEADER`）
- `app/main.py`（只讀：路由自動註冊的方式）
- `app/modules/iam/sign_in/router.py`（只讀：目前頁面怎麼用 Jinja）

## 完成條件

1. `app/core/static/htmx.min.js` 是 npm 套件 `htmx.org@2.0.11` 的 `dist/htmx.min.js`，一個位元組都沒有改。證據：`npm pack htmx.org@2.0.11` 的 `integrity`（sha512）與下載的 tarball 相符的 CLI 輸出，以及檔案的 `sha256sum`。
2. 版本與 sha256 記在 `app/core/pages.py` 的常數 `HTMX_VERSION`、`HTMX_SHA256`；`tests/unit/core/test_static_assets.py` 計算檔案的 sha256 並與常數比對。檔案被換掉或改動時測試失敗。
3. `GET /static/htmx.min.js` 不需要登入，回傳 200、`Content-Type` 為 JavaScript，內容與 repo 中的檔案相同（測試比對 sha256）。路由放在 `app/modules/system/static_assets/router.py`，由 `app/main.py` 自動註冊；不得修改 `app/main.py`。只供應這一個檔案，不開放整個目錄（避免路徑穿越）。
4. 共用版型 `app/core/templates/base.html`：
   - 用 `<script src="/static/htmx.min.js">` 載入 HTMX（不連外部 CDN）。
   - 已登入時，`<body>` 帶 `hx-headers`，內容是 JSON `{"X-CSRF-Token": "<token>"}`，以 Jinja 的 `tojson` 產生，放在單引號屬性內；未登入時不帶。
   - 提供 `title` 與 `content` 兩個 block。
5. `app/core/pages.py` 提供一個函式讓各 feature 的 router 回傳頁面，例如 `render_page(request, conn, template_dir, name, context)`：讀 session cookie，以 `anti_forgery_token_for` 取得 token，Jinja 的搜尋路徑同時包含該 feature 的 `templates/` 與 `app/core/templates/`，讓 feature 的模板可以 `{% extends "base.html" %}`。這個函式不延長 session 的閒置計時（D-078：只有 `get_current_actor` 算使用）。
6. `tests/unit/core/test_pages.py` 至少涵蓋：已登入時 `hx-headers` 解析成 JSON 後等於該 session 的 token；未登入時沒有 `hx-headers`；呼叫 `render_page` 前後 session 的最後使用時間不變；頁面含有 `/static/htmx.min.js` 的 script。
7. 用 Playwright 在本機確認：一個 `{% extends "base.html" %}` 的頁面上，`hx-post` 送出的請求帶有正確的 `X-CSRF-Token`，`app/core/session.py` 的檢查因此通過；拿掉 `hx-headers` 時被拒絕為 `FORBIDDEN`。測試用的頁面與路由只放在 scratch 目錄，不提交。證據：腳本與輸出貼在 PR 說明。
8. 不修改 `app/core/session.py`、`app/main.py`、登入頁（登入頁不需要 CSRF，維持 T-101 的寫法）。
9. 不新增 Python 依賴。
10. CI 全綠。
11. 每一條完成條件都附上證據：CLI 輸出貼在 PR 說明。
12. PR 說明依 `.github/PULL_REQUEST_TEMPLATE.md` 填寫，並在「需要 Kuei 知道的設計選擇」寫出 `render_page` 的介面，供 T-201～T-203 使用。
