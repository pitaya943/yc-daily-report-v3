# T-307 CI 的 Playwright 冒煙測試

## 目標

D-099 的畫面行為（篩選無效時清空清單、停用匯出連結）只有瀏覽器抓得到，pytest 抓不到（M2 T-205 的 Verifier：兩個畫面變異只有 Playwright 抓到）。在 CI 加一個用真的瀏覽器跑的冒煙測試，之後改壞畫面時 CI 會變紅（D-120）。

## 要讀的檔案

只讀這些，不要載入其他 feature 檔。

- `AGENTS.md`
- `docs/decisions.md` 的 D-031、D-099、D-108、D-120
- `docs/ci-checks.md`
- `.github/workflows/ci.yml`
- `spec/features/RPT-F03-history-and-export.feature` 的 RPT-R23
- `app/modules/reports/history_and_export/templates/`（要測的畫面）
- `docs/pitfalls.md` 的 #31、#33

## 完成條件

1. `tests/e2e/` 有一組 Playwright（Node 版，pitfall #33）冒煙測試：啟動真的 app 與本機 PostgreSQL，建立測試資料、以管理員登入，在 `/review/history/ordinary` 從表單送出無效篩選，斷言：完整的錯誤字串顯示在畫面上、清單清空、「匯出 Excel」連結停用（不可點，也沒有指向舊篩選的 href）；之後送出有效篩選，清單與匯出連結恢復。等待依 pitfall #31（等該次回應與 swap 完成，不用 `networkidle`）。
2. 冒煙測試只透過 HTTP 與瀏覽器操作 app，不 import 產品程式；資料準備可以用 `scripts/dev/` 的既有指令或 `tests/e2e/` 內的腳本，只連本機資料庫（`app/core/local_url.py` 的防線照常生效）。
3. CI 在每個 PR 與 `milestone/**`、`main` 的 push 上執行它。優先加在既有的 `tests` job 內（已是必要檢查）；若 `scripts/ci/checks.py` 的 `check_tests` 守衛不允許，或必須另開 job，停下來告訴 Chief（新 job 要 Kuei 加進 branch protection 才會擋合併）。
4. Node 與 Playwright 固定版本：`package.json` 與 `package-lock.json` 提交進 repo，CI 用 `npm ci`；只安裝 Chromium。
5. 證明它真的會抓到退步：在本地分別做兩個變異（不清空清單；不停用匯出連結），冒煙測試各自失敗；還原後通過。貼上指令與輸出。不要推送變異。
6. `docs/ci-checks.md` 加一列說明這個檢查、會讓它失敗的情況與本地執行的指令。
7. 不改任何產品程式、`spec/**`、`tests/steps/**`；現有的 pytest 全部照常通過。
8. CI 全綠，並在 PR 說明寫出這個步驟增加的執行時間（從 CI 的 log 取）。
9. 每一條完成條件都附上證據：CLI 輸出貼在 PR 說明。這張 ticket 沒有畫面（`screens: false`），冒煙測試失敗時的截圖可以放 `docs/evidence/T-307/` 但不強制。
10. PR 說明依 `.github/PULL_REQUEST_TEMPLATE.md` 填寫。
