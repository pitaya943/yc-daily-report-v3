# T-308 改密碼後的 session、鎖定與解除鎖定（規格更新）

## 目標

依 Kuei 在 issue #40 的決定（D-123、D-124）與 D-126，修改 T-305 的程式：

- 自己改密碼後，同一帳戶的其他 session 結束，目前這個保留；被管理員重設後，該帳戶全部的 session 結束（IAM-R33）。
- 改密碼時輸入錯誤的目前密碼，與登入共用同一個帳戶失敗計數與鎖定；鎖定期間改密碼為 `LOCKED`（IAM-R34）。
- 管理員可以提前解除鎖定（IAM-R08，D-126）。

## 完成條件

1. 下列規則的 8 個 scenario 全部通過，而且在實作前先確認它們會失敗：`IAM-R08`（3）、`IAM-R33`（2）、`IAM-R34`（3）。
2. 這些規則 ID 已加入 `tests/implemented.txt`。
3. IAM-R04～R07、IAM-R30～R32 仍全部通過；IAM-F02 既有步驟的語意不變（例如 `the failure count for … is …` 斷言的是登入寫入的列，不要拿來斷言解除鎖定）。
4. 失敗計數與鎖定只有一份：改密碼呼叫 `sign_in_lockout_and_rate_limit` 既有的記錄失敗、判斷鎖定的函式，不另寫一份；鎖定當下的 `ACCOUNT_LOCKOUT` 稽核與登入相同。錯誤的目前密碼不計入來源位址的頻率限制（IAM-R07，D-124）。
5. 規格沒有寫「正確的目前密碼是否重置失敗計數」：不要實作重置（維持只有登入成功、鎖定結束、15 分鐘沒有失敗才重置，IAM-R05），在 PR 說明列為未解問題。
6. 結束 session 只動該帳戶的 session，不影響其他帳戶；被結束的 session 之後的受保護請求為 `UNAUTHENTICATED`。
7. 新增步驟前先 `grep -rn` 同文字（pitfall #26）；IAM-F02 已定義的步驟（`has 4 failed sign-ins in the last 15 minutes`、`was locked 5 minutes ago`、`with actor SYSTEM`）直接使用。不得在 `tests/steps/common/` 新增步驟。
8. 每個拒絕案例斷言三件事：結果類別、完整錯誤字串、資料沒有任何變動。
9. 比規格更嚴格的斷言要在 PR 說明逐條列出（D-091）。
10. CI 全綠。
11. 每一條完成條件都附上證據：CLI 輸出貼在 PR 說明；畫面（改密碼後另一個瀏覽器被登出、鎖定時改密碼的錯誤訊息）附截圖，存在 `docs/evidence/T-308/`。
12. PR 說明依 `.github/PULL_REQUEST_TEMPLATE.md` 填寫。
13. 解除鎖定（IAM-R08，D-126）：端點 `POST /accounts/{id}/unlock`，清除該帳戶的鎖定與失敗計數，寫一列 `ACCOUNT_UPDATE`（說明含「解除鎖定」）。權限：ADMIN 只能解除 USER；OWNER 能解除 USER 與 ADMIN；OWNER 帳戶沒有人能解除（`FORBIDDEN`）；USER 一律 `FORBIDDEN`；被拒絕都寫 `ACCESS_DENIED`。對沒有鎖定的帳戶解除為 `CONFLICT`、不帶錯誤字串、資料不變（規格沒寫，用補充測試把關並在 PR 說明列出）。不影響來源位址的頻率限制。帳戶管理頁的按鈕由 T-304 加（D-126），這張只做端點；證據用 CLI。
14. 管理員重設密碼要有密碼確認欄（D-127）：不一致時 `INVALID`「兩次輸入的密碼不一致」，資料不變；IAM-R31 的步驟一併送確認欄，T-305 的補充測試若因此要改，只能改成送確認欄，不得刪除或放寬斷言。
15. IAM-R30 的兩列「錯誤的目前密碼」已移到 IAM-R34 的 Scenario Outline「A wrong current password is rejected and counted」（D-140）。在 `tests/steps/IAM-F06/` 定義新步驟 `the only change is one more failed sign-in for "<who>"`：這個動作恰好新增或更新一列 `sign_in_failures`（該帳戶失敗次數加 1），其他資料表（含 `sign_in_attempts`、`audit_log`）完全不變。不改 `tests/steps/common/`。
16. 規格只寫 `the request is rejected as …`、沒有資料斷言的拒絕 scenario，用補充測試斷言資料沒有任何變動（`FORBIDDEN` 只多 1 列 `ACCESS_DENIED`）；AGENTS.md 不可違反第 5 條（D-129）。
17. 登入與改密碼的競爭（D-141，issue #49）：登入在建立 session 前，於帳戶鎖（`for no key update`；`for update` 會與 `sign_in_failures` 外鍵的 key share 鎖死結，T-308 Verifier 實測，見 M3 報告）內重新確認密碼雜湊沒有在比對之後被改變；改變了就拒絕，與密碼錯誤相同處理（`UNAUTHENTICATED`「密碼錯誤，請重試」、記一次失敗、不建立 session）。不需要 migration；不改登入其他行為，IAM-R01～R07 照常通過。在 `tests/steps/IAM-F06/` 加並行補充測試：登入比對通過後、建立 session 前改密碼，最後不得留下有效的 session；拿掉重新確認的變異必須讓測試失敗。
