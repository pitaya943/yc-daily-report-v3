# T-204 至少一個工項與共同作業者資格（規格更新）

## 目標

依 Kuei 在 issue #29 的決定（D-096、D-097、D-103），修改 T-201、T-202 的程式：

- 全部為 0 的回報不成立，送出與編輯都拒絕；自訂工項有數量也算（RPT-R08、RPT-R14）。
- 不符資格或重複的共同作業者改為拒絕，不再靜默略過（RPT-R05）。
- RPT-R03 的邊界表改寫了步驟文字（加填一個有數量的工項）。

RPT-R03、RPT-R05 已由 Chief 暫時從 `tests/implemented.txt` 移除（D-103），這張 ticket 把它們加回去。

- `AGENTS.md`
- `docs/decisions.md` 的 D-093～D-097、D-103

## 完成條件

1. 下列規則的 scenario 全部通過，而且在實作前先確認它們會失敗：`RPT-R03`（1）、`RPT-R05`（4）、`RPT-R08`（1）、`RPT-R14`（2）。
2. 這些規則 ID 已加入 `tests/implemented.txt`（RPT-R03、RPT-R05 是加回去）。
3. 每個拒絕案例斷言三件事：結果類別、完整錯誤字串、資料沒有任何變動。
4. 伺服器重新驗證每個欄位；缺少的值不以預設值補上。
5. 「至少一個工項」的判斷只寫一份，送出與編輯共用；自訂工項有數量時算有工項（D-096 B1）。共同作業者：不符資格（不同區、不同類型、封存、非 USER、提交者自己、不存在）或同一人出現兩次，回 `INVALID`「共同作業者最多 6 人，且須為同一區域、同一類型的啟用員工」，資料不變。
6. 其他已實作的規則（RPT-R01、R02、R04、R06、R07、R10～R13、R20～R23、IAM-R10）仍全部通過。若某些既有步驟的實作原本送出全部為 0 的回報（例如只帶共同作業者的送出步驟），改成另外帶一個有數量的工項；步驟文字不變。
7. **不得刪除或改名任何既有測試**（D-052）。若既有的補充測試寫死了舊行為而必須改變，停下來告訴 Chief，由 Chief 在 ticket 寫明處理方式。
8. 畫面：送出與編輯被這兩條規則拒絕時，畫面顯示完整錯誤字串。截圖存在 `docs/evidence/T-204/`（至少：送出全部為 0、選了不符資格的共同作業者、編輯成全部為 0）。
9. 比規格更嚴格的斷言要在 PR 說明逐條列出（D-091）。
10. CI 全綠。
11. 每一條完成條件都附上證據：CLI 輸出貼在 PR 說明；有畫面的功能附截圖。
12. PR 說明依 `.github/PULL_REQUEST_TEMPLATE.md` 填寫。
