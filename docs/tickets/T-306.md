2. 這些規則 ID 已加入 `tests/implemented.txt`。
3. 每個拒絕案例斷言三件事：結果類別、完整錯誤字串、資料沒有任何變動。
4. 伺服器重新驗證每個欄位；缺少的值不以預設值補上。
5. CI 全綠。
6. 每一條完成條件都附上證據：CLI 輸出貼在 PR 說明；有畫面的功能附截圖，存在 `docs/evidence/T-306/`。
7. PR 說明依 `.github/PULL_REQUEST_TEMPLATE.md` 填寫。
8. 儲存與加密（D-113）：migration 新增銀行帳號（只存密文）與發薪方式（`TRANSFER` 或 `CASH`，既有帳戶為 `CASH`，D-116）。加密用 `cryptography` 的 AES-256-GCM（每次加密用新的隨機 nonce），金鑰從環境變數 `BANK_NUMBER_KEY`（base64 的 32 bytes）讀取；`pyproject.toml` 加 `cryptography` 並固定版本範圍。金鑰缺少或格式不對時依 IAM-R43；程式與紀錄都不印出金鑰或完整帳號。測試用的金鑰只在測試中設定，不提交真的金鑰。
9. USER 不能讀別人的銀行帳號（D-114）：`FORBIDDEN` 並寫 `ACCESS_DENIED`，用補充測試把關（規則 IAM-R42 在 M4 的 T-406 轉綠）。
10. 路徑（D-118）：`GET /accounts/{id}/bank-number`（遮罩，不寫稽核）、`POST /accounts/{id}/bank-number/reveal`（寫 `BANK_REVEAL`）、`POST /accounts/{id}/bank-number`（設定）、`POST /accounts/{id}/payment-method`。顯示完整帳號是 `POST`，因為 T-200 的補充測試要求「渲染頁面時整個資料庫不變」。
