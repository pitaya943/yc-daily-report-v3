## 完成條件

2. 這些規則 ID 已加入 `tests/implemented.txt`。
3. 每個拒絕案例斷言三件事：結果類別、完整錯誤字串、資料沒有任何變動。
4. 伺服器重新驗證每個欄位；缺少的值不以預設值補上。
5. CI 全綠。
6. 每一條完成條件都附上證據：CLI 輸出貼在 PR 說明；有畫面的功能附截圖，存在 `docs/evidence/T-303/`。
7. PR 說明依 `.github/PULL_REQUEST_TEMPLATE.md` 填寫。
8. IAM-R14（銀行帳號與改為轉帳）移到 T-306（D-113）。這張 ticket 不建立、不讀寫銀行帳號與發薪方式的欄位。
9. 薪資設定的初始值（D-116）：勞健保扣除額 0、未投保、個人未投保比例空白（用區域比例）、未投保免扣關、固定薪資 0、每期發放固定薪資關。既有帳戶由 migration 設成同樣的值；建立帳戶時不必送這些欄位。
10. USER 不能讀別人的勞健保扣除額與未投保比例（D-114）：`FORBIDDEN` 並寫 `ACCESS_DENIED`，用補充測試把關（規則 IAM-R42 在 M4 的 T-406 轉綠）。
11. 路徑（D-118）：`GET/POST /accounts`（清單、建立）、`GET/POST /accounts/{id}`（資料與薪資設定）、`POST /accounts/{id}/archive`、`POST /accounts/{id}/restore`；IAM-R19 的 `POST /accounts/{id}/delete`、`POST /accounts/{id}/deactivate` 一律 `INVALID`。T-304 之後會在這個目錄加上「只有 OWNER 能動 ADMIN」的檢查（D-115），所以權限判斷集中在一處，方便它加。
12. 建立帳戶要有密碼確認欄（D-127，附錄 B「設定密碼時」）：與密碼不一致時 `INVALID`「兩次輸入的密碼不一致」，資料不變；IAM-R13 的步驟一併送確認欄。補充測試把關。
13. 顯示名稱（D-139）：建立與修改時先去掉前後空白（含全形空白）再檢查長度與重複；只有空白時為 `INVALID`「請輸入顯示名稱」。補充測試至少涵蓋 `Wen ` 與 `Wen` 視為重複、全形空白。
14. 規格只寫 `the request is rejected as …`、沒有資料斷言的拒絕 scenario，用補充測試斷言資料沒有任何變動（`FORBIDDEN` 只多 1 列 `ACCESS_DENIED`）；AGENTS.md 不可違反第 5 條（D-129）。
